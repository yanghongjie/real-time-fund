## Context

基基宝是一个纯前端基金估值追踪工具，用户希望能够追踪实际投资收益。当前应用只展示涨跌幅百分比，无法直观看到盈亏金额。

**约束条件：**
- 纯前端应用，无后端服务
- 使用 localStorage 存储（5MB 限制）
- 需兼容现有数据结构和功能

## Goals / Non-Goals

**Goals:**
- 允许用户为每只基金设置持仓金额
- 基于持仓金额和涨跌幅计算当日收益
- 显示投资组合汇总信息（总资产、总收益）
- 数据持久化并支持导入导出

**Non-Goals:**
- 不追踪历史收益记录
- 不计算累计收益（需要买入成本）
- 不支持多账户/多组合管理
- 暂不支持基金份额设置（仅金额）

## Decisions

### Decision 1: 使用持仓金额而非份额

**选择**: 存储持仓金额（CNY）

**理由**:
- 用户更关心投入了多少钱，而非具体份额
- 简化计算逻辑：`当日收益 = 持仓金额 × 涨跌幅%`
- 避免需要用户查询精确份额数

**备选方案**:
- 存储份额：需要额外计算 `份额 × 净值 = 金额`，用户设置门槛高

### Decision 2: localStorage 数据结构

**选择**: 独立存储 `positions` 对象

```javascript
// localStorage key: 'positions'
{
  "110022": 10000,  // 基金代码: 持仓金额
  "519674": 5000
}
```

**理由**:
- 与现有 `funds` 数组解耦，减少数据迁移风险
- 便于独立管理持仓数据
- 符合现有 localStorage 使用模式

### Decision 3: 收益计算公式

```javascript
// 当日收益计算
dailyProfit = position × (changeRate / 100)

// 其中 changeRate 优先使用：
// 1. estGszzl (有效持仓覆盖率 > 5% 时的估算涨跌幅)
// 2. gszzl (官方估值涨跌幅)
```

### Decision 4: 汇总信息显示位置

**选择**: 在添加基金区域下方、基金列表上方显示

**理由**:
- 用户进入页面后首先看到总体情况
- 不影响现有基金列表布局
- 符合常见投资 App 的信息架构

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| localStorage 容量限制 | positions 数据量小，影响极低 | 监控存储使用 |
| 估值数据不准确 | 收益计算会有误差 | 界面提示"仅供参考" |
| 用户输入错误金额 | 收益显示不符预期 | 允许随时修改 |

## Migration Plan

1. 新功能为增量添加，不影响现有数据
2. 首次使用时 positions 为空对象，汇总信息不显示
3. 导入旧版配置文件时自动兼容（无 positions 字段）
